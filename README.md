# 通勤离线音乐 PWA（核心验证版）

纯 HTML / JavaScript，无依赖、无构建。支持本地多文件导入、URL 下载、离线音频存储、列表删除、播放/暂停/上一首/下一首、自动循环下一首、每首进度及上次曲目恢复、Media Session 锁屏控制。

## 本地运行

在仓库根目录执行：

```bash
python3 -m http.server 8000
```

电脑浏览器打开 **http://localhost:8000**。不能直接双击 `index.html`：Service Worker 需要安全上下文（HTTPS 或 localhost）。首次打开需联网，等页面提示“应用外壳已缓存”后再测试离线。

本地音频通过文件选择器批量导入。URL 导入会先完整下载文件，再写入 IndexedDB；只支持 HTTP/HTTPS 音频直链。远程服务器必须允许 CORS，HTTPS 页面不能下载 HTTP 混合内容。普通网页地址、登录页面及流媒体播放列表不受支持。可以把音频临时放在本仓库目录，用 `http://localhost:8000/sample.mp3` 测试同源 URL 下载；该测试文件无需加入 Git。

## 手机安装

1. 将本目录以静态站点部署到 **HTTPS** 地址，或使用带可信证书的本地 HTTPS 服务。手机与电脑同网并访问 `http://电脑局域网IP:8000` 可以打开页面，但这不是安全上下文，无法完成 PWA 离线能力验证；手机上的 localhost 指手机自身。
2. Android：使用 Chrome 打开 HTTPS 地址，在浏览器菜单选择“安装应用”或“添加到主屏幕”（不同版本名称有差异）。
3. iPhone/iPad：使用 Safari 打开 HTTPS 地址，点击分享，选择“添加到主屏幕”。
4. 从主屏幕打开应用，导入音频并等待保存完成。浏览器页面和主屏幕应用的存储可能因平台而异，建议在实际使用的入口内导入并测试。

安装是可选的：支持 Service Worker 的浏览器标签页也可离线使用。

## 验证步骤

1. 导入至少两首浏览器支持的音频（如 MP3），确认列表显示名称。再通过音频 URL 下载一首，等待“下载并保存完成”。
2. 播放、暂停、拖动进度，点击上一首/下一首、列表曲目切换；把进度拖到结尾，确认自动下一首（最后一首后循环至第一首）。单曲列表会循环该曲。
3. 在两首曲目分别播放或拖到不同位置，暂停后刷新或关闭再打开应用。应恢复上次曲目及位置；点击另一首也应恢复该曲位置。为遵守浏览器自动播放限制，重启恢复后保持暂停，需主动点击播放。
4. 等“应用外壳已缓存”后，电脑开发者工具 Network 选 Offline 并刷新；也可停止 Python 服务再刷新。应仍能打开应用并播放已导入音频。开发者工具不要勾选“Bypass for network”。手机可开启飞行模式、关闭 Wi-Fi，再从主屏幕重新打开，验证播放和切歌。离线时不能下载新的 URL。
5. 播放时锁屏或打开系统媒体控制面板，验证曲名、播放/暂停、上一首/下一首。也注册了快进、快退和跳转操作；系统是否显示这些按钮取决于浏览器和操作系统。
6. 删除曲目并刷新，确认没有重新出现；删除当前曲目会停止播放并清空当前选择，下一次可从列表选择。

## 存储与限制

- IndexedDB 数据库 `commute-music` 保存音频 Blob、曲目信息及播放状态。Service Worker 仅缓存应用外壳，音频播放使用 IndexedDB 创建的 Blob URL，不依赖远程音频服务器。
- 播放中约每两秒保存进度，暂停、拖动、页面隐藏时也保存。强制杀进程可能丢失最近几秒；普通关闭后可恢复已提交的数据。
- 此验证版启动时读取全部音频 Blob，适合少量曲目验证；没有大音乐库优化、转码、后台下载、导出或云同步。
- 存储仅限当前设备、浏览器和站点来源（协议、主机和端口）。清除站点数据、隐私模式结束、浏览器回收存储都会导致曲目丢失，请保留原始音频；导入超过配额会显示错误。
- 格式支持、Media Session、锁屏后持续播放行为由浏览器/系统决定。尤其移动系统可能暂停后台页面，PWA 不能保证进程始终存活。
- 更新应用外壳时修改 `sw.js` 的缓存版本；激活时仅清理本应用旧版外壳缓存，不删除音乐库。

node --check app.js
